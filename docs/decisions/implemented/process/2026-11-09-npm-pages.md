# Agent Note: npm 与 GitHub Pages 发布约定

Status: implemented

## Problem

用户要求当前 Firefly 项目统一为 npm，并推送到 lanyugod/lanyugod.github.io。原安装门禁、锁文件、工作区、工作流和文档仍依赖 pnpm；远端 main 分支是 Hexo 源码，本地目录没有 Git 元数据。

## Decision

项目使用 Node.js 24 和 npm 11，package-lock.json 是唯一依赖锁文件。安装使用 npm ci；开发、检查、构建、NAS 导出和 GitHub Actions 均使用 npm scripts。移除 pnpm 安装门禁、配置和锁文件，registry 使用官方 npm 源，保留原有直接依赖版本范围。站点信息组件及其翻译显示 npm 版本。

npm overrides 将 @cloudflare/vite-plugin 的 wrangler 依赖对齐根目录 wrangler：插件同时将 wrangler 声明为直接依赖与 peer dependency，原 pnpm 锁文件使用根目录 4.147.0，而插件清单中的直接依赖固定为 4.127.1。该 override 保持原有依赖选择。TypeScript 脚本通过 node --import tsx 运行，复用 tsx loader；它不需要 tsx CLI 的 IPC 监听，在当前受限环境中也可运行。

发布工作流在 main 或 master 推送及手动触发时执行 npm ci、检查、测试、笔记校验、构建及站点校验，上传 dist 后发布 GitHub Pages。站点域名沿用 blog.lanyu.dev，PUBLIC_MEDIA_ORIGIN 沿用原有可选 NAS 设置。推送应以远端现有 main 为父提交保留历史，工作树只包含当前 Firefly 项目。

本篇接管[当前 Firefly 结构笔记](../../../../.agents/notes/implemented/architecture/2026-11-09-firefly-blog.md)中的包管理与发布工具约定，其余运行时约定仍有效。环境禁止写入 .agents，因此现行工具约定记录在 docs/decisions。

## Alternatives considered

- 继续使用 pnpm：可以直接复用原有锁文件，但不符合用户统一 npm 的要求。
- 直接让 npm 采用插件固定的 Wrangler 4.127.1：无需 override，但会引入与原 pnpm 锁文件不同的 Wrangler 版本，因此保留原解析选择。
- 重新初始化并强制覆盖远端历史：操作较少，但远端已有正式提交，保留历史的普通提交可以表达这次源码替换，无需 force push。

## Consequences

本地和 CI 使用同一种包管理器，npm ci 以锁文件固定版本和完整性。锁文件包含 Linux、macOS 等平台的可选原生依赖，不依赖本地 pnpm 链接或镜像源。以后升级 Cloudflare 依赖时需要复查 wrangler override。

锁文件由 npm Arborist 使用原有依赖清单和缓存解析生成，完整性来自原锁文件；当前环境无法连接 npm registry，不能完成在线的全新 npm ci 安装。GitHub 连接器没有已安装的仓库授权，写入返回 403，用户选择暂时不推送，当前未修改远端或发布。

## Testing

实际检查结果见[当前验证结果](../../../verification.md)。npm ci --dry-run 验证锁文件与 package.json 一致；它不能替代联网后的 npm ci 和 GitHub Actions 发布验证。
